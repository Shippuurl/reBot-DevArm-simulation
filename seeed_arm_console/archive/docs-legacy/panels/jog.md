# Jog 与轨迹

Jog 面板用于低速点动和发送已经验证的轨迹。TCP 联调模式已提供使能、停用、停止和 ±0.05 rad 点动按钮；正式执行仍由控制网关完成安全检查。

## 关节 Jog

每个 Jog 请求应包含：

```text
session_id
joint_name
direction（正 / 负）
step（角度或弧度）
speed_limit
command_id
client_timestamp
```

按住按钮时使用短周期命令或速度模式，松开后必须发送停止/保持命令。不要让客户端直接积累未确认的 Jog 队列。

## 位姿 Jog

笛卡尔 Jog 需要明确参考坐标系（base、tool 或 world）、平移/旋转轴、步长和速度。网关在发送到规划器前检查工作空间、关节限位、奇异位形和碰撞约束。

## 轨迹下发

轨迹分为“预览”和“执行”两个阶段：

1. 客户端上传带时间戳、单位和坐标系的轨迹。
2. 网关校验点数、时间单调性、速度/加速度/限位和当前模式。
3. 规划器或仿真器返回摘要与警告。
4. 操作员确认后生成一次性执行令牌。
5. 驱动执行并持续发布实际轨迹，异常时进入停止流程。

## 单位和精度

协议内部统一使用 SI 单位：弧度、弧度每秒、牛顿米、米和秒。UI 可以显示角度和毫米，但在发送前必须显式转换并在界面标明单位。

## 交互安全

- 未连接或未使能时禁用运动按钮。
- 速度限制和步长限制由网关强制执行，UI 只是辅助输入。
- 轨迹执行按钮显示目标时长、最大速度、点数和校验结果。
- 急停优先级高于所有普通命令，不能排在普通队列之后。
