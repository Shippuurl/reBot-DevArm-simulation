# 项目介绍

## 为什么做这个项目

传统机器人上位机往往把 UI、驱动、规划和可视化写在同一个进程里，容易出现渲染卡顿、硬件适配困难和仿真环境难以复现的问题。本项目将这些职责拆开：

1. Win11 原生 `eframe/egui` 负责操作员界面。
2. 控制协议描述连接、使能、Jog、轨迹和故障，不绑定某一家硬件。
3. ROS 2 Jazzy 桥接节点负责与 Docker 内的 ROS 2 图和驱动通信。
4. OpenRAVE 与 MuJoCo 分别提供规划/IK 和动力学仿真能力。
5. Rerun 负责记录与查看，不进入实时安全控制闭环。

## 技术选型

| 层 | 当前选型 | 选择理由 |
| --- | --- | --- |
| 桌面 UI | Rust、eframe、egui、egui_dock | 原生性能、跨平台、适合高频状态刷新 |
| 图表 | egui_plot（计划） | 控制面板内的轻量时序曲线 |
| 三维与记录 | Rerun SDK/Viewer | 模型、TF、图像、点云、轨迹统一记录 |
| 通信 | ROS 2 + gRPC/WebSocket | ROS 生态兼容，跨进程边界清晰 |
| 缓冲 | crossbeam-channel、triple_buffer（计划） | UI 与遥测解耦，始终读取最新状态 |
| 规划 | OpenRAVE headless | 现有环境可复现，不引入 MoveIt |
| 仿真 | MuJoCo（计划） | 适合动力学和控制回放验证 |

## 术语

- **控制命令**：连接、使能、Jog、位姿或轨迹等由操作者发出的请求。
- **遥测**：关节状态、TF、力/力矩、图像、点云和诊断状态。
- **安全监督器**：在命令抵达驱动前执行模式、限位、超时和急停检查的组件。
- **记录层**：将状态转换为 Rerun 时间线事件的桥接，不负责发出运动命令。
