# 设计决策（ADR）

这里记录会影响接口和部署方式的长期决策；功能进度和验证记录见[实施计划（进度与验证）](/simulation-work-plan)。

## ADR-001：SDK 是业务程序的入口

**状态：已采纳**

**决策**　Python、C++、Rust 业务程序通过对应 SDK 调用 `ArmPlanner` 和 `ArmGateway`。
SDK 对外提供语言原生类型，protobuf 生成代码留在库内。

**原因**　业务代码只面对稳定的控制、规划和遥测 API，平台可以独立替换规划器、仿真器
或 Viewer。ROS 2 作为编排适配层接入同一接口。

**影响**　协议字段变更需要同步三个 SDK；Viewer 的 Rerun 实体由 Viewer 自己管理。

## ADR-002：gRPC 是服务边界

**状态：已采纳**

**决策**　`protocol/arm_console.proto` 定义 `arm.console.v1`。`ArmGateway` 提供握手、
控制和遥测，`ArmPlanner` 提供 IK 与轨迹规划。

**原因**　gRPC 同时覆盖本机进程、容器和跨语言客户端；请求 ID、会话和时间戳可以在协议
层统一处理。

**影响**　控制和规划集成遵循 gRPC；50052 JSON 用于本机诊断与 Rerun 转发。

## ADR-003：Rerun 是观察层

**状态：已采纳**

**决策**　Viewer 订阅遥测并负责 3D、时间线、记录和回放。控制面板通过 SDK 把命令发给
网关，Rerun recording 不参与控制状态机。

**原因**　显示频率、历史缓存或 Viewer 生命周期不应改变执行状态，也不应阻塞控制请求。

**影响**　规划和执行服务可以在 Viewer 运行时独立重启；记录异常只影响可视化。

## ADR-004：网关做最终执行输入校验

**状态：已采纳**

**决策**　规划结果先提交网关预检，再由网关在正式入队前复核会话、命令新鲜度、轨迹时序、
有限值、关节限位和速度。Planner 返回的 Coal 碰撞检查结果随规划结果交给业务程序；
Gateway 不在执行入口重复计算碰撞几何。

**原因**　规划器输出的是候选结果，执行侧必须在同一入口收敛输入规则，并能独立于规划
服务完成格式和运动边界检查。碰撞几何依赖模型和规划场景，由 Planner 统一计算。

**影响**　业务程序应保留“规划 → 预检 → 执行”的顺序；真实设备还要把硬件急停、限位和
watchdog 接入设备安全链路。

## ADR-005：分阶段交付仿真保真度

**状态：已采纳**

**决策**　当前 MuJoCo 适配器的交付范围是运动学状态采样、接触重算、传感器输出和协议
闭环；动力学性能指标单独作为后续里程碑，不与 SDK 或 Viewer 功能完成度混为一谈。

**原因**　现有执行适配直接更新关节状态并调用 `mj_forward`，尚未接入经过校准的执行器、
质量/惯量、摩擦和控制器参数。没有这些参数，速度、负载、跟踪误差和接触力不能代表设备
额定性能。

**影响**　计划中的性能结论必须注明模型适用范围，并以参数来源、校准方法和真机对照数据
作为动力学验收条件；SDK、规划和可视化可以在此之前独立交付。
